0 · Pornire

o singură comandă

Din folderul qorder, în Git Bash (Docker pornit):

USE_DB=1 bash demo.sh

Așteaptă Pornesc BFF pe http://<IP>:8080 + lista de linkuri + compilarea app-ului. Scriptul îți afișează IP-ul LAN (ex. 192.168.100.86). Peste tot mai jos, <IP> = ăla.

Verificare rapidă: deschide http://<IP>:8080/health → trebuie ok. Testează în Incognito, ca să nu ai sesiuni vechi salvate.

2 · Client (comandă)

fluxul de bază
  1. Deschide http://<IP>:8082/#/t/7
    Se încarcă meniul „Demo Pub", masa 7 pre-completată. Culorile brandului (fundal închis, portocaliu).
  2. Caută în meniu + filtrează „Doar disponibile acum"
    Lista se filtrează. Un produs în afara orelui apare indisponibil.
  3. Adaugă 2-3 produse în coș, apasă coșul
    FAB-ul arată numărul + totalul. Coșul listează liniile + totalul corect.
  4. Scrie numele, apasă Trimite → confirmă în dialog
    Dialog cu tabel + total. La confirm: comandă trimisă, apare statusul „Așteaptă".
  5. Adaugă alte produse după trimitere
    Butonul revine la „Trimite comanda" (nu rămâne pe „Comandă nouă").

3 · Ospătar

cod 2468
  1. Deschide /#/waiter → cod 2468
    Apare surface-ul ospătarului cu comanda trimisă la pasul 2, în „Comenzi noi".
  2. Apasă Confirmă pe comandă
    Trece în „În lucru". Pe telefonul clientului statusul devine Preluată.
  3. Apasă Gata, apoi Livrat
    Statusul clientului avansează Gata → Livrat (bannerul verde la „gata").
  4. Din client: Cheamă ospătarul / Adu nota
    Apare în secțiunea Cereri la ospătar. Rezolvă → dispare.

4 · Patron + Setări

cod 1357
  1. Deschide /#/owner → cod 1357
    Dashboard „Patron · sumar": comenzi azi, încasări, timpi medii, grafice.
  2. Sus dreapta ⚙ → Setări → schimbă o culoare din paletă + numele
    Previzualizarea se schimbă live pe măsură ce alegi.
  3. Apasă Salvează
    Apare „Salvat." (dacă dă „Verifică accesul de patron", ai token vechi → logout + login).
  4. Refresh la meniul de client /#/t/7
    Meniul are culorile / numele noi — schimbarea a ajuns la client.

5 · Operator (admin)

token demo-operator
  1. Deschide /#/admin → token demo-operator → Încarcă
    Tabel cross-venue: localuri active, comenzi, utilizatori (din datele reale).
  2. Trimite un log de client (simulează o eroare):
    curl -X POST http://<IP>:8080/logs -H "Content-Type: application/json" -d '{"records":[{"level":"error","message":"test","venueId":"demo"}]}'
    Reîncarcă /admin → la „Erori recente" apare linia cu chip roșu „error", mesaj, local.
  3. Token greșit în /admin
    Mesaj de eroare, nu ecran gol.

6 · Fidelitate

OTP 000000
  1. Client: „Devino client fidel" / Intră cu telefonul → orice număr → cod 000000
    Te loghezi. Apare chip-ul de puncte în bara de meniu, contul „Contul meu".
  2. Plasează o comandă ca client logat, apoi vezi Recompense
    Punctele cresc din cheltuială. O recompensă accesibilă se poate Folosi (cod pentru ospătar).
  3. Ospătar: validează codul de recompensă
    Recompensa se marchează folosită; punctele s-au scăzut.

7 · Securitate (trebuie să REFUZE)

izolare + acces
  1. Cod greșit la /#/owner sau /#/waiter
    Refuzat — „Cod greșit".
  2. GET /logs fără token operator
    403 forbidden.
  3. Salvare Setări cu token de staff (nu owner) — vezi în bff/demo-bff.log
    Log: auth refused: role staff is not owner + 403.
  4. Inundă POST /logs de peste 60 de ori rapid
    Ultimele răspund 429 (rate-limit).

Unde te uiți la loguri

  1. Server: tail -f bff/demo-bff.log
    Startup (mod storage), fiecare request, motivul oricărui 403/auth refuzat.
  2. Client: în browser F12 → Console
    Logurile clientului (tag qorder). Debug complet doar în build debug.
Coduri de demo, nu de producție. <IP> îl afișează demo.sh la pornire. Persistența reală (config, comenzi, loguri) necesită USE_DB=1.
